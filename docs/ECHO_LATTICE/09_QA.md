# Echo Lattice — 09_QA.md

**Slice:** 09. Quality Assurance
**Status:** Locked for MVP demo. Reviewed once per grammar / habit-profile
version bump.
**Companion code:** [`game/echo_lattice/`](../../game/echo_lattice/) — the
project this document is written against.

> Echo Lattice's selling point is that the chamber is a **pure function
> of the player**. If that function ever returns an unsolvable chamber,
> or two players with the same buffer see different chambers, the
> product loses its identity. This QA slice exists so those two things
> can be answered with an automated pass/fail instead of a vibe check.

---

## 0 Scope

- The **MVP scope** covered by this matrix:
  - `Lattice` grid + I/O helpers.
  - `MoveBuffer` capture, capacity handling, canonical hash.
  - `HabitProfile` classification into `DASH_HEAVY`, `LOOPY`, `HESITANT`,
    `NEUTRAL`.
  - `Grammar` rewrite transforms and the `safe_apply` / `apply_deck`
    wrappers.
  - `Solver` BFS reachability and shortest-path.
  - `LatticeGenerator` end-to-end pipeline.
- **Out of scope for MVP QA** (tracked in later slices): rendering,
  audio, controller glyphs, Steam Cloud saves, accessibility toggles.
  A checklist per subsystem is deferred to `10_ACCESSIBILITY.md` and
  `11_STEAMWORKS.md`.

## 1 Test taxonomy

| Layer | Runner | Location | What it proves |
|---|---|---|---|
| Unit — pure data | headless GDScript (this repo) or [GUT](https://github.com/bitwes/Gut) | `game/echo_lattice/tests/test_lattice.gd`, `test_move_buffer.gd`, `test_habit_profile.gd`, `test_solver.gd` | Data structures behave as documented. |
| Property — rewrite invariants | headless GDScript / GUT | `test_habit_rewrite_invariants.gd` | Grammar honours algebraic and safety invariants. |
| Property — solvability | headless GDScript / GUT | `test_maze_solvability.gd` | Every generated chamber is solvable and deterministic. |
| Integration — chamber pipeline | headless GDScript / GUT | `test_maze_solvability.gd::test_generator_*` | The whole (seed, buffer) → lattice path holds under deterministic + fuzzed input. |
| Smoke — session boot | manual (editor) | tracked in `10_ACCESSIBILITY.md` | Booted editor scene renders a chamber. |
| Manual — feel / juice | manual playtest | Playtest notes | Rewrite-beat readability, audio identity. |

Automated coverage sits at the unit + property + integration layers.
Manual coverage is deliberate — feel-check work is not falsifiable and
does not belong in CI.

## 2 Running the automated suite

### 2.1 Headless (default; no plugins required)

```bash
cd game/echo_lattice
godot4 --headless --import .          # once, to build the class cache
./tests/run_tests.sh                  # thereafter
```

The wrapper resolves `GODOT` from the environment if set, otherwise
requires `godot4` on `PATH`. Exit code is `0` when every test passes and
`1` if a single assertion fails, so it plugs directly into any CI runner
that treats non-zero as failure. Output on the current Linux build:

```
Totals: 42/42 passed (0 failed) in 360ms
```

### 2.2 Under GUT

The tests extend a shared `EchoLatticeTestBase` (see
[`tests/test_base.gd`](../../game/echo_lattice/tests/test_base.gd)) that
mirrors GUT conventions: `test_*` methods, `before_each` / `after_each`
hooks, and per-test failure collection. To run under GUT once the plugin
is installed:

1. Install the GUT plugin into `game/echo_lattice/addons/gut/`.
2. Change `extends EchoLatticeTestBase` to `extends GutTest` in each
   test file (a two-line search-and-replace) — the assertion API is
   nominally compatible; `assert_lattices_equal` is a helper local to
   this project and lands as a plain equality check under GUT.
3. Run `godot4 --headless --path game/echo_lattice -s res://addons/gut/gut_cmdln.gd -gdir=res://tests -gexit`.

The headless runner in `test_runner.gd` is the primary CI path so the
project is not blocked on the GUT plugin being present.

## 4 Invariants under test — the "why", plainly

### 4.1 Solvability

For every `(seed, width, height, MoveBuffer)` the game will realistically
ask the generator to serve:

```
Solver.is_solvable(LatticeGenerator.generate(seed, w, h, buffer)) == true
```

This is enforced from three angles:

- **Fixed grid** — small enumerated cross-product of grid sizes ×
  deterministic seeds × canonical habit buffers (`M-01` … `M-03`).
- **Fuzz** — a randomised sweep (`M-04`) whose RNG seed is a constant so
  a failure is reproducible from the printed values. Bump
  `FUZZ_ITERATIONS` on suspicion.
- **Grammar layer** — the `safe_apply` wrapper is itself covered by
  `R-10`, so the generator's guarantee decomposes cleanly.

### 4.2 Rewrite invariants

The grammar exposes six transforms. Each row of the group table below
must hold; the property tests spell them out:

| Property | Test |
|---|---|
| `identity(L) = L` | R-02 |
| `mirror_h(mirror_h(L)) = L` | R-03 |
| `mirror_v(mirror_v(L)) = L` | R-04 |
| `rotate_180(rotate_180(L)) = L` | R-05 |
| `mirror_h(mirror_v(L)) = rotate_180(L)` | R-06 |
| Isometries preserve (w, h, START count, DOOR count) | R-07 |
| Isometries preserve solvability and shortest path length | R-08, R-09 |
| `safe_apply` never returns invalid or unsolvable | R-10 |
| `apply_deck` is a pure function of (L, deck, seed) | R-11 |
| `apply_deck` is order-sensitive when a content edit is present | R-12 |
| `apply_deck` preserves START and DOOR count | R-13 |
| Habit → deck mapping is pinned | R-14 |

### 4.3 Habit rewrite invariants

Where "habit" enters the picture explicitly:

- **B-03, B-04** — the buffer's hash isolates *behaviour* from
  *coincidence*: order matters, capacity matters. This is what keeps
  "same buffer, same chamber" from becoming "same last move, same
  chamber".
- **H-01 … H-05** — the classifier's decision boundary. Changing a
  threshold in `HabitProfile` requires updating both these tests and
  R-14 (the deck pinning).
- **R-14** — the label → deck mapping the generator uses. Explicit so a
  drive-by refactor cannot silently reassign transforms.
- **M-03** — every non-neutral profile still yields a solvable
  chamber; the buffer cannot construct an unsolvable one by accident.

### 4.4 Determinism

The whole product depends on:

- `MoveBuffer.hash_code()` being platform-stable (B-02, B-04).
- `LatticeGenerator.generate()` being a pure function of its arguments
  (M-05).
- `Grammar.apply_deck()` being a pure function of its arguments (R-11).

A change to any RNG mixer or hash constant is a **versioned** change:
save files, ghost paths and daily seeds are keyed off these outputs.

## 5 Release gate checklist

Ticked automatically by the headless suite; humans still confirm the
manual rows.

- [x] All 42 automated tests green (`./tests/run_tests.sh`).
- [x] Suite runtime under 2 s on a warm cache (measured: **~0.4 s** on
      Godot 4.3 headless Linux).
- [ ] `--import` step also runs green from a cold `.godot/` (CI job).
- [ ] Manual smoke: boot the editor, run the first chamber, hit the
      first checkpoint, confirm the "rewrite" audio + visual beat.
- [ ] Manual ghost-race: two Steam accounts, same seed, same recorded
      moves — chambers overlay pixel-perfectly.
- [ ] Accessibility smoke — colourblind lattice palette, hold-to-walk
      binding (tracked in `10_ACCESSIBILITY.md`).

## 6 Regression policy

- Any bug that ships to a demo or Next Fest build lands **as an
  automated test first**, in the file matching the invariant it
  violates.
- Test IDs (`M-04`, `R-10`, …) are stable. Do not renumber; add.
- Change to a Grammar constant (`_mix32` multipliers, RNG masks) is a
  save-format bump. Update `docs/ECHO_LATTICE/08_DATA_MODEL.md` and the
  save version constant in the same commit.
- Change to a HabitProfile threshold is a rules bump. Bump the label
  version stored alongside the buffer.

## 7 Known gaps and follow-ups

- **Grammar expansion.** The current test bed covers 6 transforms.
  Additional transforms (thicken variants, spiral, WFC packs) will land
  each with an involution / commutativity / solvability row.
- **Large-lattice performance.** Solver BFS is `O(W×H)`. Not yet
  benchmarked at target chamber size × transform-deck depth; add a
  performance test file when the chamber authoring tool lands.
- **Multi-checkpoint chains.** Right now each generator call is a
  single-checkpoint slice. A "wing" of 6–10 chambers wires them
  together; the wing-level invariants (progression, cumulative
  difficulty, no dead-end wings) get their own QA slice in
  `12_PROGRESSION_QA.md`.
- **Save-round-trip.** Once `08_DATA_MODEL.md` locks the on-disk format,
  add a byte-for-byte save/load round-trip test using the same fuzz
  seeds as M-04.
- **GUT parity CI job.** Optional — nice-to-have, not blocking. Once
  added, use both runners on every commit; a divergence between them is
  a runner bug, not a test bug.
